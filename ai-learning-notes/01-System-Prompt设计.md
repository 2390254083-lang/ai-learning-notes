# Day 1：System Prompt 设计原则

> 第 1 周 · Prompt Engineering
> 用时：1-2 小时

---

## 一、System Prompt 是什么

你调用 API 时，每次发两条消息给 AI：

| 角色 | 作用 | 类比 |
|------|------|------|
| **System Prompt** | 设定 AI 的身份、行为规则、输出格式 | 给员工发的工作手册 |
| **User Prompt** | 这次具体要做什么 | 给员工布置的当天任务 |

你的插件里已经在用了——`background.js` 里 `defaultPrompts` 那个对象就是 system prompt：

```js
summarize: '你是一个专业的文本总结助手。请用简洁的中文总结...'
translate: '你是一个专业翻译助手。请将用户提供的文本翻译成...'
explain: '你是一个耐心的知识讲解员。请用通俗易懂的中文解释...'
```

---

## 二、三条核心原则

### 原则 1：角色设定越具体，输出越稳定

❌ 差的：`"你是一个助手"`
✅ 好的：`"你是一个专业的技术文档翻译，擅长把英文技术博客翻译成中文，保留代码和术语不翻译，语气保持原文风格"`

**为什么有效：** AI 的训练数据里，"技术文档翻译"这个角色对应的是特定的语言风格和准确性要求。角色越具体，它就越不容易跑偏。

### 原则 2：给约束，不要只给愿望

❌ 差的：`"翻译得流畅一些"`
✅ 好的：`"翻译规则：1. 代码块不翻译 2. 专业术语首次出现时保留英文并括号标注中文 3. 每段不超过 3 句话"`

**为什么有效：** AI 不理解"流畅"，但它理解"每段不超过 3 句话"。把形容词变成可执行的规则。

### 原则 3：给示例比给规则更有效（Few-shot）

❌ 没有示例：全靠描述
✅ 给了示例：`"示例输入：The quick brown fox → 示例输出：敏捷的棕色狐狸"`

**为什么有效：** 大模型本质是"模式匹配器"，给它看一个例子，比描述十遍规则管用。

## 三、直接用插件做实验

### 实验 1：对比"有角色"vs"没角色"

**A 版（没角色）：**
```
把这段文字翻译成中文。
```

**B 版（有角色）：**
```
你是《环球时报》英文版的中文译者，擅长把英文新闻翻译成地道的中文新闻语言，保留新闻的时效感和客观性。
```

### 实验 2：对比"模糊约束"vs"精确约束"

**A 版（模糊）：**
```
总结这段文字，简洁一点。
```

**B 版（精确）：**
```
你是会议纪要撰写专家。总结规则：
1. 控制在 3 个要点以内
2. 每个要点不超过 40 个字
3. 不要复述原文句子，用自己的话概括
4. 如果原文包含数据或数字，必须保留
```

### 实验 3：加一个例子试试

在 B 版的基础上，末尾加一句示例：
```
示例：
原文："China's GDP grew 5.2% in 2024, beating market expectations."
总结：中国 2024 年 GDP 增长 5.2%，超市场预期。
```

---

## 四、关键一句话

> System Prompt 不是在"告诉 AI 做什么"，而是在"塑造 AI 是谁"。角色越具体、规则越精确、例子越充分，输出就越可控。
